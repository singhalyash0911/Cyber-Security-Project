AES-256-GCM Authenticated Encryption

Symmetric Algorithm Used in SecureStego Core

This demonstration reuses the project's production module (encryption.py). AES-256-GCM is an AEAD (Authenticated Encryption with Associated Data) scheme: it provides both confidentiality (secrecy) and authenticity/integrity (tamper detection) using a 128-bit authentication tag.

Key & Salt

A 256-bit symmetric key is derived from the password using PBKDF2-HMAC-SHA256 (100,000 rounds) and a fresh 16-byte random salt to prevent rainbow table attacks.

Nonce (12 Bytes)

A cryptographically random 96-bit Number used ONCE (os.urandom(12)). Reusing a nonce with the same key destroys GCM security.

Auth Tag (16 Bytes)

Galois Hash authentication tag. If even 1 bit of ciphertext, salt, or nonce is altered, decryption immediately fails with an authentication error.

Caesar Cipher (Substitution Cipher)

Classical Cryptography Demo
Important Educational Notice: The Caesar cipher is intended strictly for academic demonstration of monoalphabetic substitution ciphers. It is completely insecure for protecting confidential data because its key space is limited to only 25 possible shifts (easily cracked by hand in seconds) and it preserves letter frequency patterns (e.g. 'E', 'T', 'A' in English).

In a substitution cipher, each character in the plaintext is systematically replaced by another character. In Caesar cipher with shift $k$, character position $p$ is mapped to $c = (p + k) \pmod{26}$.

RSA Public & Private Key Asymmetric Encryption

Python Cryptography (OAEP-SHA256 Padding)

Asymmetric cryptography uses mathematically linked key pairs: a Public Key (which can be distributed openly to the world) and a Private Key (which must remain secret). Messages encrypted with the public key can only be decrypted by the matching private key.

Key Constraints & Modern Standards: This educational demo uses 2048-bit RSA with OAEP (Optimal Asymmetric Encryption Padding) and SHA-256. Plain textbook RSA ($c = m^e \pmod n$) is deterministic and insecure; OAEP introduces randomized hashing. Because RSA operations are computationally intensive, RSA in real-world systems is used for key exchange or digital signatures, not for large payload steganography.

SHA-256 One-Way Cryptographic Hash Function

Integrity Verification & Avalanche Effect

A cryptographic hash function takes arbitrary-length input data and maps it to a fixed-size digest (256 bits / 32 bytes / 64 hexadecimal characters). Hashing is strictly one-way: it is computationally impossible to reverse the digest back into the original plaintext.

Crucial Distinction: Hashing vs. Encryption
  • Encryption is two-way: ciphertext is created with a key and can be decrypted back to plaintext.
  • Hashing is strictly one-way: there is no key and no decryption function.
  • Password Warning: Plain SHA-256 should never be used for password storage without salting and computational stretching (e.g. PBKDF2), because attackers can compute billions of plain hashes per second using GPUs or precomputed rainbow tables.

MCA Cyber Security & Cryptography Syllabus Guide

Quick Theoretical Concepts for Viva & Exams

Concise academic summaries of fundamental cryptography topics commonly required in the MCA curriculum, providing context for modern and historical security techniques.

1. Transposition Ciphers

Unlike substitution ciphers (which replace characters), transposition ciphers permute or rearrange the positions of letters without altering their identities.

  • Rail Fence Cipher: Writes plaintext in a zigzag pattern across multiple rails and reads off row by row.
  • Columnar Transposition: Characters are written into a matrix of fixed columns and read out column-wise ordered by an alphabetical key.
  • Cryptanalysis: Preserves original character frequency counts (letter 'E' remains the most frequent), making single transposition vulnerable to anagramming.
Shannon's Principle: Diffusion

2. Block vs. Stream Ciphers

Symmetric ciphers are divided into two fundamental operational architectures:

  • Block Ciphers (e.g., AES, DES): Encrypt fixed-size blocks (e.g. 128 bits). Requires padding (PKCS#7) when data is not an exact multiple. Operational modes include ECB (insecure pattern leakage), CBC (chaining with IV), and GCM (counter-based authenticated encryption).
  • Stream Ciphers (e.g., ChaCha20, RC4): Generates a continuous pseudorandom keystream XORed bit-by-bit or byte-by-byte with plaintext. No padding required; ideal for real-time media streams.
AES-GCM is an AEAD Block Mode

3. DES & Its Security Limitations

Adopted by NIST in 1977 based on IBM's Lucifer cipher, the Data Encryption Standard (DES) uses a 64-bit block size and a 16-round Feistel network.

  • 56-Bit Effective Key: Out of 64 key bits, 8 are parity bits, leaving only $2^{56} \approx 7.2 \times 10^{16}$ possible keys.
  • Brute-Force Vulnerability: In 1998, EFF's "Deep Crack" broke DES in 56 hours. Today, modern GPUs crack 56-bit DES in minutes.
  • Triple-DES (3DES): Interim fix applying $E(k_1, D(k_2, E(k_3, m)))$ giving 112 or 168 effective bits, but deprecated due to slow performance and 64-bit Sweet32 collision attacks.
Superseded by AES (128/192/256 bits)

4. Key Management Principles

Kerckhoffs's Principle: A cryptographic system must remain secure even if everything about the design (algorithms, parameters) is public knowledge, as long as the key is secret.

  • Key Lifecycle: Generation (high-entropy CSPRNG), Distribution (secure exchange/PKI), Storage (HSMs, TPMs, encrypted memory), Rotation, and Secure Erasure (zeroing).
  • Key Derivation (KDF): Transforming human passwords into cryptographic keys using algorithms like PBKDF2 or Argon2 with unique salts and thousands of iterations.
Foundation of Defense-in-Depth

5. Diffie–Hellman Key Exchange

Published by Whitfield Diffie and Martin Hellman in 1976, this protocol enables two parties to establish a shared symmetric secret over an untrusted, eavesdropped communication channel.

  • Mathematical Hardness: Relies on the difficulty of the Discrete Logarithm Problem in cyclic groups: given $g^a \pmod p$, it is computationally infeasible to recover $a$.
  • Exchange Flow: Alice transmits $A = g^a \pmod p$, Bob transmits $B = g^b \pmod p$. Alice computes $B^a \pmod p$ and Bob computes $A^b \pmod p$, yielding identical shared secret $g^{ab} \pmod p$.
  • Modern Evolution: ECDH (Elliptic Curve Diffie-Hellman) provides smaller keys and higher efficiency.
Solves the Key Distribution Problem

6. Digital Signatures

An asymmetric cryptographic primitive that provides Authenticity (proves sender identity), Integrity (message not altered), and Non-Repudiation (sender cannot deny).

  • Signing Mechanism: Sender computes a cryptographic hash $H(M)$ of the message and encrypts the hash with their private key: $Sig = E_{priv}(H(M))$.
  • Verification Mechanism: Any verifier decrypts the signature with the sender's public key and compares it against their own locally calculated $H(M)$.
  • Contrast: Encryption uses recipient's public key (confidentiality); Digital signatures use sender's private key (authenticity).
Core of PKI & TLS Certificates
